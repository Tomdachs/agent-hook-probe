# Security policy

## Reporting a vulnerability

Please do not open a public issue for a vulnerability that could expose credentials, private hook payloads, transcript data, or allow unexpected command execution.

Use GitHub private vulnerability reporting when available. Otherwise contact the repository owner privately through the GitHub profile before public disclosure.

## Security design expectations

- Provider processes are launched with argument arrays, never through a shell.
- Live fixtures contain only probe-owned config, hook commands, records, and canaries.
- Existing provider config, hooks, credentials, and user repositories are never modified.
- Codex runs with `workspace-write`; approval and sandbox bypasses are forbidden.
- Hook-trust bypass is limited to the exact disposable hook file generated by the probe for that invocation.
- Subprocesses and hook handlers have bounded timeouts.
- Raw hook payloads are temporary and excluded from normal reports.
- Kept fixtures are an explicit debugging opt-in and may contain local paths and probe session metadata.

Hooks are useful guardrails but are not a complete security boundary. A missing hook can be exactly the failure this project is designed to detect.
